**FIXED — user-reported (2026-08-12): combined view showed no live progress / analysis results.**

**FIXED — user-reported (2026-08-12): calibration hardware pill never updates + sweep "stuck at J" at start.**

## 1. Executive Summary

The application is architecturally sound in its bones — the layering (procedures / instruments / analysis / GUI), the optional SPO module isolation, the crash-safe SPO logging, and the block-tag CSV format are all well designed, and **all 131 tests pass**. However, the audit found **6 Critical, 15 High, ~20 Medium and ~25 Low findings**. The most consequential fall into three clusters:

1. **Scientific correctness (data validity)** — the SPO drift sign is inverted (degrading cells are reported as improving), Vmpp loses its sign so p-i-n cells are SPO-held at the **wrong polarity**, truncated sweeps fabricate Voc values (verified: a cell with true Voc = 914 mV swept only to 750 mV reports **Voc = 4829 mV** into the CSV), and the hardware sweep can silently return a corrupted final data point when the voltage range is not an integer multiple of the step.
2. **Safety & stability (hardware/threads)** — Abort cannot de-energize the Keithley while a sweep read is blocking; the SPO worker thread is never joined before instruments are disconnected; closing the Calibration window with ✕ leaves the output energized; a missing `QtWidgets` import crashes **every** combined JV+SPO run at completion and soft-locks the app.
3. **Security & robustness** — OTPs are generated with non-cryptographic `random`, password reset is gated only by client-side UI state, a plaintext `admin/admin` database is committed to the repo and shipped in the package, session audit logs are silently empty, and SMTP TLS certificates are never verified.

None of these findings invalidate data taken from **complete, well-formed forward sweeps on n-i-p cells** — the core unit chain (Jsc, EFF, FF on complete curves) was verified correct to ~1–2%. The problems concentrate at the edges: reverse/hysteresis handling, p-i-n polarity, truncated/dark curves, aborts, and error paths.

## 3. Critical Findings

### C1 — Combined JV+SPO mode crashes on completion and soft-locks the app
`gui/app_controller.py:1081, :1270` use `QtWidgets.QMessageBox` but the module only imports `QtCore` at top level (the `QtWidgets` import at :473 is local to `load_files`). Every combined run ends in `NameError` inside a Qt slot. The `:1081` branch raises **before** state reset and instrument disconnect → `is_busy=True` forever, instruments connected, all run buttons dead until restart. Also `:1273` reads `_combined_best_channel` *after* the reset nulled it.
**Fix:** module-level `from PyQt5 import QtWidgets`; capture `best_channel` before `_reset_combined_state()`.

### C2 — Closing CalibrationWindow with ✕ leaves the Keithley energized — **FIXED**
`windows/calibration_window.py` had no `closeEvent` override. ✕ during a running calibration sweep: worker keeps sweeping, no `:OUTP OFF`, no disconnect, and `main.py` falls through to `sys.exit(0)` with the source on. `JVAnalyzerWindow.closeEvent` (:986–1011) does this correctly — mirror it.
**Fixed** by a `closeEvent` that aborts, de-energizes, disconnects and ends the session (test: `tests/gui/test_calibration_close_event.py`).

**C2a — regression caused by that fix (2026-09, FIXED).** The hand-off to the main window *also* closes the calibration window: `_on_proceed`/`_on_skip` emit `calibration_passed` and then `close()`, and the slot (`main.py`'s `launch_main_app`) runs **synchronously**, so `closeEvent` fired inside the hand-off and ran the full shutdown — including `disconnect_keithley()`, which `close()`s the VISA session the main window had just been handed. Because each window built its *own* `InstrumentManager` and only the instrument *objects* were copied across, the main window kept a non-None handle to a closed session: `connect_keithley()` short-circuited on `if self.keithley: return`, the status light showed green, and the first sweep died at `_ensure_idle`'s `:OUTP OFF` with `pyvisa.errors.InvalidSession` (verified against a real 2026-09-09 lab log). The same `closeEvent` also called `SessionManager.end_session()`, removing the root-logger file handler (the failure was never written to the session log) and clearing `current_user` (closing the main window bounced back to the login dialog instead of exiting).
**Fixed** by (a) one process-wide `InstrumentManager` passed to every window instead of copied instrument references, (b) a `_handed_off` flag so `closeEvent` shuts hardware down only on a real close, (c) session-liveness checks (`visa_session_open` / `is_keithley_alive`) driving the status lights, the calibration readiness gate, a self-healing `connect_keithley`/`connect_mux`, and a pre-flight gate in `AppController` that fails fast with an actionable message instead of a raw traceback from the worker thread. Tests: `tests/gui/test_calibration_handoff.py`, `tests/instruments/test_instrument_manager_session.py`.

### C3 — Abort cannot de-energize the output during a sweep; cross-thread VISA races
`procedures/jv_procedure.py:452–461`: the whole hardware sweep is one blocking `:READ?` (timeout up to 3× sweep time) on the worker thread; `should_stop()` is unreachable during it. Abort merely sets a flag — the Keithley stays ON at the sourced voltage until the sweep finishes. Meanwhile `resume_experiment` (`app_controller.py:839`) and `closeEvent` write `:OUTP OFF`/`:ABOR` from the **GUI thread on the same non-thread-safe PyVISA session** the worker is blocked on.
**Fix:** switch to `:INIT` + status-polling (`*OPC`/MAV) with short timeouts, checking `should_stop()` between polls; serialize all VISA access behind one lock.

### C4 — SpoWorker (QThread) never joined; teardown races on close/logout
No `.wait()` exists anywhere in `src/`. `closeEvent`/logout set the abort flag then immediately write `:OUTP OFF` and close the VISA session while the worker may be mid-`:READ?` or mid-CSV-row → "QThread: Destroyed while thread is still running" hard crash, exceptions in the dying thread, indeterminate instrument state.
**Fix:** `worker.wait(timeout)` after `abort()`, before any disconnect, in every teardown path.

### C5 — Password reset requires no server-side proof of OTP; OTPs from non-crypto `random`
`auth/database.py:201–236`: `reset_password(username, email, new_pw)` succeeds on username+email alone — OTP verification only enables a text field in the UI (`login_dialog.py:554`). Anyone knowing a colleague's username+email can reset their password with three lines of Python. Compounding it, `email_service.py:331` generates OTPs with `random.randint` (Mersenne Twister, predictable) instead of `secrets`.
**Fix:** `secrets.randbelow(1_000_000)`; make `verify_otp` return a short-lived token that `reset_password` requires.

### C6 — Plaintext `admin/admin` SQLite DB committed and shipped
`src/solarjv_analyzer/users.db` is in the repo and inside the packaged `sources`; `utils/database.py` seeds `("admin","admin")` in plaintext. Verified nothing imports it today — but it ships in every wheel/installer and is one import away from re-enabling plaintext auth.
**Fix:** delete `users.db` and `utils/database.py`; add `*.db` to `.gitignore`.

## 5. Medium & Low Findings (condensed)

**Hardware/timing:** float truncation off-by-one (`int(1.4/0.2)=6`) makes NPLC use 7 points where 8 are generated → delivered sweep rate ~14% slower than requested, and would misalign the dormant dual-sweep split (`jv_procedure.py:288,680`); NPLC clamp to 0.01 silently violates the requested rate; autoranging (default) adds unmodeled per-point latency — the recorded "sweep rate" is nominal, not actual; several-second uncontrolled, unrecorded dark gap between forward and reverse sweeps (matters for perovskite hysteresis); no VISA device-clear after read timeout (stale response can poison the next query); a garbled SPO sample kills a multi-hour hold instead of retrying once; VISA adapter leaked on failed connect — with `ASRL3::INSTR` (exclusive serial) this **bricks reconnection until app restart** (`instrument_manager.py:16–33`); `pre_sweep_delay` applied twice; bare `except:` around MUX deselect can silently leave two pixels connected in parallel.

**GUI:** combined runs ignore Single-Sweep-Mode (key read from the wrong dict — always queues reverse); combined-run inputs never locked (`set_config_enabled` has zero callers) so mid-run edits leak into the SPO phase; logout confirmation aborts the measurement *before* the final "are you sure"; `Clear all`/`Open` live during runs (Open → `manager.clear()` orphans the running worker) and Clear-all has no confirmation; PyMeasure `failed` signal never connected (failures visible only in the log); checklist dialog is a one-shot dead end if dismissed with ✕; no hardware-reconnect affordance after "Hardware Disconnected"; Proceed/Skip hand instruments to the main window while an abort is still in flight; SPO re-enable ignores filename validity; combined Instrument tab shows stale NPLC; blocking VISA connects and SMTP calls on the GUI thread (freezes up to full socket timeout); ✕-closing the main window relaunches the login dialog instead of exiting.

**Analysis details:** clamping fabricates operating points off the measured curve (both clamps together → FF = 100% exactly) and unconditionally discards the polynomial Pmax value; quintic on ≥6 points is an exact interpolant (no smoothing) and systematically underfits sharp MPP knees (−1.6% Pmpp verified); the "argmin fails at local maxima" justification is mathematically wrong (argmin is global by definition); FF guard compares to exact zero — a near-dead pixel yields FF ~10²⁸ %; `noise_current_a` parameter is decorative; Rs/Rsh 20-point window is count-based not voltage-span-based (biases Rsh at coarse steps); Voc regression direction (V on I) inverts the instrument's error model; SPO energy integrates |P| (counts consumption as yield); Quick JV hard-codes `incident_power=100`.

**Auth/files:** email case handling inconsistent across four call sites → duplicate accounts possible (no UNIQUE on email) and a password-reset dead-end *after* consuming the OTP; OTP cooldown bypass (verified); registration dead-ends entirely when SMTP is unreachable (no user can be created); no email-format validation; username not sanitized → path traversal or `OSError` from `os.makedirs`; `DirectoryManager.__init__` silently discards args on re-login → stale deleted parent widget → `RuntimeError` → process abort; SPO mode switch not in `try/finally` (exception strands the singleton in "SPO" mode — CLAUDE.md warns about exactly this); date rollover at midnight splits a run across folders; loaded-file temp CSVs never deleted; block-tag parser breaks if Notes contain `[[`; `[[ NOTES ]]` written but never read back; abort leaves only `*_temp.csv` files and never merges a partial report; `config.py` fields without annotations aren't dataclass fields at all (frozen-ness is illusory, `tests/config` only tests a real field); `MUX_PORT` changeable only by editing source; stray `import os` inside the class body; `DATE_FORMAT` constant exists but `directory_manager.py` hardcodes its own; Argon2 never rehash-checked; `email_verified` column written but never read; OTP comparison not constant-time; registration TOCTOU → raw `IntegrityError` escapes the `except ValueError`.

## 6. What Was Verified Correct

The audit deliberately looked for things done right; these deserve to stay as-is:

- **Unit chains** for Jsc (A/cm²→mA/cm²), EFF (mW/cm²·cm²·10⁻³), FF (computed in V·A before mV display conversion) — all exact; the suspected "FF from mV" bug does **not** exist.
- **Quadrant-agnostic core math** (P=V·I<0 mask) verified identical magnitudes for Q2/Q4; SCPI staircase command set, `:FORM:ELEM` parse order, buffer-limit guard (2500), NPLC clamp bounds, auto-zero ×3 accounting, and `_safety_abort` ordering (`:OUTP OFF` before `:ABOR`) are all correct per Keithley 2400 behavior.
- **SPO absolute-time scheduling** (`next_sample += interval`) is drift-free — correctly not naive `sleep(interval)`; **fsync-per-row is real** (flush + `os.fsync` every row, graceful `OSError` fallback); raw vs. report paths deliberately kept distinct to avoid clobbering.
- **SQL injection: clean** — every query in the auth layer is parameterized; login error message is non-enumerating; the runtime auth DB lives in the correct per-user writable location with WAL and closed connections in `finally`; schema migrations are idempotent.
- **OTP arithmetic** (3 attempts, single-use, 10-min expiry, sliding window) is correct except the cooldown-bypass noted above.
- **No duplicate signal connections, no lambda late-binding bugs**; the Quick-JV button lifecycle and the Advanced JV⇄SPO guard-and-revert are model implementations; `is_busy` set synchronously does prevent double-enqueue; channel numbering is consistent 1-based GUI → 0-based MUX end to end.
- **CSV block tags** round-trip correctly including the 3-row MultiIndex header and legacy Vmax/Jmax tolerance.

## 7. Functionality Gap Analysis (vs. commercial software & standards)

Benchmarked against Ossila I-V, Fluxim Litos, Keithley KickStart, Enlitech IVS-KA6000, Oriel PVIV, Wavelabs SINUS, and IEC 60904-1/-7, IEC 60891, and the ISOS consensus protocols (Khenkin et al., *Nature Energy* 2020). Verdict: **at parity with mid-tier commercial JV-scan software; one generation behind perovskite-specialist tools on stability methodology** — and most of the distance is closable in software on the existing hardware.

### Must-have
1. **MPP tracking mode for stability runs (G1).** Fixed-voltage SPO systematically mis-measures stabilized power as Vmpp drifts; ISOS names MPP tracking the preferred aging bias, and every perovskite-relevant competitor ships it. A perturb-and-observe tracker is ~30 lines in the existing `SpoWorker` loop plus a toggle and CSV column. *Effort: low-medium, no new hardware.*
2. **Hysteresis quantification + stabilized/scan-PCE ratio (G2).** FW/RV pairs are measured but no hysteresis index, scan-rate annotation, or SPO-to-scan-PCE ratio is ever computed — all reviewer expectations for perovskite claims. Pure computation on existing data. *Effort: trivial.*
3. **Configurable pre-sweep conditioning recorded in metadata (G3).** Bias/soak history strongly affects perovskite J-V; ISOS requires reporting it. A timed pre-bias hold + two parameter fields. *Effort: low.*

### Should-have
4. **Lifetime/aging mode (G4):** periodic quick-JVs interleaved with the hold, parameter-vs-time trending (T80). The 6-channel MUX makes this a poor-man's Litos. *Medium.*
5. **Temperature logging (G5):** IEC 60904-1 requires device temperature; add at minimum a manual entry field now, sensor integration later. *Medium (hardware).*
6. **Wavelabs simulator control (G6):** the lab's SINUS has a TCP/XML API; automating recipe/shutter removes the biggest human-error source in the calibration gate and unlocks G7/G9/light-soaking. *Medium.*
7. **Dark J-V mode with diode analysis (G7):** semilog plot, ideality factor n, J0 — standard recombination diagnostic; pure-computation analysis addition. *Low-medium.*
8. **Irradiance/mismatch metadata (G8):** propagate the calibration measurement into Pin instead of discarding it; add a spectral-mismatch-factor input (IEC 60904-7) and reference-cell ID/date to the parameters block. *Trivial-low.*
9. **PDF report (G9):** `reportlab` is already a declared dependency with zero implementation; the login+calibration provenance chain makes a signed-off PDF genuinely differentiating. *Low.*

### Nice-to-have
Intensity-dependent JV / Suns-Voc (G10), asymptotic steady-state Pmax scan (G11 — note: conflicts with the hardware-staircase design, needs a software-stepped engine), run-comparison overlays and plot-image export (G12), IEC 60891 corrections (G13).
